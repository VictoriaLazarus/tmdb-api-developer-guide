TMDB supports two authentication models: **API v3** and **API v4**. Both give access to TMDB resources, but they serve different purposes and authenticate differently.

## API v3

API v3 is the original TMDB API and remains the most widely used version. It supports both public data retrieval and authenticated user actions through session-based authentication.

Read-only endpoints can be authenticated with a Bearer token or an API key. Endpoints that modify user-specific data (ratings, favorites, watchlists) require a valid **v3 session ID**, created through the authentication workflow using a request token approved by the user.

This guide uses the v3 workflow throughout:

1. Create a request token.
2. Approve the request token.
3. Exchange the approved token for a session ID.
4. Call authenticated endpoints with the session ID.

## API v4

API v4 introduces a modern authentication model built around user-authorized access tokens. Instead of session-based authentication, v4 uses [OAuth-style](https://oauth.net/2/access-tokens/) token authorization, so users explicitly grant an application permission to access their TMDB account.

Some endpoints support converting a user-authorized v4 token into a v3 session, which lets an application reach endpoints that still require session-based authentication. That conversion requires the user to grant **write permission** during authorization.

## Which one should you use

| If you are… | Use |
| --- | --- |
| Reading public data (search, discover, movie details) | v3 Bearer token |
| Performing user actions (rate, favorite, watchlist) | v3 session ID |
| Building a multi-user app with explicit user consent | v4 access token, converted to a v3 session where needed |

<Note>
Many user-specific endpoints still rely on the v3 session workflow, which is why this guide focuses on v3 authentication.
</Note>
