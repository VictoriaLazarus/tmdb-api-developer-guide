TMDB provides two API versions, **v3** and **v4**. Both provide access to TMDB resources, but they differ in their endpoints, authentication workflows, and supported features.

## API v3

API v3 is the version used throughout this guide. It provides endpoints for retrieving movie, TV, person, account, search, and other TMDB data.

For application-level access, v3 supports an API key or an API Read Access Token sent as a Bearer token. The Bearer token can be used for requests across both v3 and v4.

For user-specific actions such as rating movies, managing favorites, and updating watchlists, v3 uses a session ID. A session ID can be created by generating a request token, approving it, and exchanging the approved token for a session ID.

This guide uses the v3 workflow for user-authenticated requests:

1. Create a request token.
2. Approve the request token.
3. Exchange the approved token for a session ID.
4. Call authenticated endpoints with the session ID.

## API v4

API v4 introduces a user authentication workflow based on **access tokens**. A typical user-authentication flow generates a request token, asks the user to authorize it on TMDB, and then exchanges the approved request token for a user access token.

A v4 access token can also be used to create a v3 session ID through the **Create Session (from v4 token)** endpoint. The v4 token must have been authorized by the user with write permission for this conversion.

This means that applications using v4 authentication can still access v3 endpoints that require a session ID.

## Choosing an authentication method

| If you need to… | Authentication |
| --- | --- |
| Make application-level requests to documented v3 endpoints | API Read Access Token or API key |
| Perform user-specific actions such as ratings, favorites, or watchlists | v3 session ID |
| Build a user-authenticated workflow using v4 | v4 access token |
| Use a v4-authorized user with an endpoint that requires a v3 session | Convert the v4 access token to a v3 session ID |

<Note>
This guide uses the v3 API and focuses on the v3 session workflow because several of the documented user-specific endpoints require a v3 session ID. The v4 workflow is covered here to explain how it differs and how a v4-authorized user can be connected to v3 session-based endpoints.
</Note>
